# Markdown Password Vault для Obsidian

**Markdown Password Vault** хранит секреты прямо в заметках Obsidian. Пароли, токены и API-ключи остаются частью обычных Markdown-файлов, но их значение записывается только в зашифрованном виде. Поэтому vault можно синхронизировать через Obsidian Sync, Git, Syncthing, Dropbox, OneDrive или другой привычный способ — отдельной базы паролей плагин не создаёт.

> Важно: плагин находится в стадии разработки. Проверьте сценарий на тестовой заметке и сохраните резервную копию vault, прежде чем переносить единственные экземпляры критически важных секретов.

## Что происходит с данными

Зашифрованный секрет выглядит так:

```text
ENC:v1:AAECAwQF...
```

`v1` — версия формата. Внутри строки находятся случайная соль, уникальный nonce (IV) и шифротекст. Для каждого секрета создаются новые соль и nonce. Плагин использует:

- Argon2id для получения ключевого материала из мастер-пароля;
- HKDF-SHA-256 для отдельного ключа каждого секрета;
- AES-256-GCM для шифрования и проверки целостности.

Мастер-пароль не сохраняется в настройках и не записывается в файлы. После разблокировки в памяти остаётся только неэкспортируемый производный ключ. При Lock, автоблокировке или закрытии Obsidian ссылка на ключ удаляется.

## Установка

1. Выполните `npm install` и `npm run build` в папке проекта.
2. Создайте каталог `<ваш-vault>/.obsidian/plugins/markdown-password-vault/`.
3. Скопируйте в него файлы `main.js`, `manifest.json` и `styles.css`.
4. В Obsidian откройте **Settings → Community plugins**, разрешите community plugins при необходимости и включите **Markdown Password Vault**.
5. Для работы плагина установите горячие клавиши в настройках плагина.
6. 

Для разработки используйте `npm run dev`: сборщик будет отслеживать изменения `main.ts` и пересобирать `main.js`.

## Быстрый старт

### 1. Разблокируйте vault

Откройте Command palette (`Ctrl/Cmd+P`) и запустите **Markdown Password Vault: Unlock vault**. Введите мастер-пароль. Он нужен только в текущем сеансе Obsidian.

Выберите длинную уникальную парольную фразу. Если забыть мастер-пароль, расшифровать уже записанные секреты невозможно.

### 2. Зашифруйте выделенный текст

Создайте или откройте заметку, выделите секрет и нажмите горячию клавишу соответствующию **Markdown Password Vault: Encrypt selection**. 
Это можно указать в настройках плагина.

До шифрования:

```markdown
GitHub

Логин: mylogin
Пароль: MyPassword123
```

После шифрования выделенного `MyPassword123`:

```markdown
GitHub

Логин: mylogin
Пароль: ENC:v1:AAECAwQF...
```

Так же можно шифровать API-ключи, access-токены, recovery-коды, seed-фразы и многострочные выделения.

### 3. Используйте зашифрованное значение

В режиме редактирования поставьте курсор на строку, содержащую только `ENC:v1:...`, и откройте контекстное меню. Доступны действия:

- **Copy decrypted secret** — расшифровать и скопировать в системный буфер;
- **Show decrypted secret** — кратко показать значение;
- **Edit decrypted secret** — изменить значение и сразу сохранить новый шифротекст;
- **Re-encrypt secret** — зашифровать то же значение с новой солью и nonce.

В режиме чтения строка `ENC:v1:...` скрыта и кликабельна. Нажатие открывает меню действий, либо выполняет выбранное в настройках действие по умолчанию: открыть меню, скопировать или кратко показать секрет.

## Шаблон карточки секрета

Команда **Markdown Password Vault: Insert secret template** вставляет заготовку:

````markdown
```secret
label: GitHub
username: mylogin
password: MyPassword123
url: https://github.com
notes: Рабочий аккаунт
```
````

Затем выделите только значение после `password:` (`MyPassword123`) и примените **Encrypt selection**. Итоговая карточка:

````markdown
```secret
label: GitHub
username: mylogin
password: ENC:v1:AAECAwQF...
url: https://github.com
notes: Рабочий аккаунт
```
````

В режиме чтения блок показывает название секрета и кнопки **Copy** и **Show**. Поля `label`, `username`, `url` и `notes` остаются обычным текстом; помещайте туда только несекретные сведения. Чтобы скрыть логин или заметки, зашифруйте их отдельными значениями `ENC:v1:...`.

## Блокировка и буфер обмена

- Выполните **Markdown Password Vault: Lock vault**, чтобы немедленно заблокировать хранилище.
- После периода бездействия плагин блокируется автоматически. Значение `0` отключает автоблокировку.
- После копирования секрет очищается из буфера через выбранный интервал. Значение `0` отключает очистку.

Если во время операции vault заблокирован, плагин запросит мастер-пароль. После разблокировки повторите действие.

## Настройки

Откройте **Settings → Markdown Password Vault**. Доступны:

- время автоблокировки в минутах;
- время очистки буфера обмена в секундах;
- действие при нажатии на секрет в режиме чтения;
- отображение иконок действий;
- информация о текущем формате шифрования: **AES-256-GCM (v1)**.

Горячие клавиши для команд Obsidian настраиваются стандартно: **Settings → Hotkeys**, затем найдите команды с префиксом `Markdown Password Vault`.

## Синхронизация и резервные копии

Синхронизируются только Markdown-файлы с уже зашифрованными строками. Настройки плагина не содержат мастер-пароля или ключей. Обычные правила для синхронизации всё равно важны:

- не разрешайте конфликты синхронизации автоматически, если два устройства одновременно редактировали один секрет;
- регулярно создавайте резервные копии vault;
- не публикуйте мастер-пароль в заметках, Git-репозитории или истории команд;
- помните: наличие шифротекста не заменяет контроль доступа к самому vault.

## Ограничения безопасности

Расшифрованное значение на короткое время может появиться в оперативной памяти, в системном буфере обмена или на экране. Не используйте плагин на скомпрометированном устройстве и не оставляйте Obsidian разблокированным без присмотра. Автоматическая очистка буфера уменьшает риск, но не может отозвать значение, уже прочитанное другим приложением.

The `secret` code block is a readable Markdown template. Encrypt its `password:` value with **Encrypt selection** before previewing it.
